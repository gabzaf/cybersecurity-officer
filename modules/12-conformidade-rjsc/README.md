# 12 — Plan for RJC / NIS2 compliance

**Keywords:** RJC · DL 125/2025 · NIS2 · MyCiber · RJSC · GRC programme · gap analysis · RACI · CNCS · essential entity · important entity · security programme

Modules 1–11 are pieces. This one is the **programme**: how an entity in scope of the **Regime Jurídico da Cibersegurança** goes from “we have a CISO on a slide” to a defensible operating model.

I learned the backlog under RJSC (2018/2021). In 2026 I would run the same sequence against **DL 125/2025** and **Reg. 756/2026**.

---

## How I would run the programme

1. **Confirm scope** — essential, important, or relevant public? Medium-enterprise thresholds? Sector overlays (**DORA**, **CER**)? Self-identify on **MyCiber**.  
2. **Name the functions** — PCP and Security Officer, reported to CNCS on the legal clock, with deputies.  
3. **Baseline** — QNRCS / CiberCheckup / CIS IG1. Gap list with risk, not traffic-light theatre.  
4. **Stand up the document set** in order: inventory → risk analysis → TOMs → PSI → security plan → IRP → annual report cycle.  
5. **RACI** — who owns inventory, risk, plan, incidents, report. The Security Officer is accountable for the file; system owners are accountable for their assets.  
6. **Calendar** — MyCiber filings, notification drills, restore tests, inventory freeze, management review before the annual report.  
7. **Board briefing** — supply chain, management liability, reporting clocks, fine exposure. Money and liability, not acronyms.

---

## Order matters

Do not write a PSI before you know the assets. Do not write a security plan before residual risk exists. Do not promise CNCS an inventory of “everything” if the filing is the internet-facing extract. Do not implement MONARC as a science fair while PCP cannot be reached at night.

---

## Interview line

“RJC / NIS2 compliance is a programme with a legal backlog, not a project with an end date. I sequence inventory, risk, measures, policy, plan, IR, and reporting so each artefact cites the previous one.”
